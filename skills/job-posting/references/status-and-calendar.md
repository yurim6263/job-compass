# 5단계: 현황표 · 5.5단계: 마감 캘린더

`Areas/취업/지원 현황.md`는 13열 표다(열·값 목록은 `_공용/references/status-values.md`). 표를 읽고 쓰는 일은 **직접 하지 않고 `status_table.py`로 한다**(열 검증·형식이 깨지면 쓰기 거부·쓰기 전 사본). 아래 명령은 볼트 루트에서 `python -I -X utf8 .claude/skills/_공용/scripts/…`로 돌린다.

## 5. 현황표 행 추가
0. 현황표가 있으면 `status_table.py check`. 문제가 나오면 쓰지 않고 사용자에게 알린다. **10열 옛 형식**이면 `status_table.py migrate`(미리보기)를 보여 주고, 사용자가 승인하면 `migrate --apply`(`--rewrite-header`는 머리말의 자리표시자·옛 문구를 새 문구로 바꿀 때)로 13열로 바꾼 뒤 계속한다.
1. **같은 공고 ID 행이 있나** — `status_table.py find --id <공고 ID>`. 있으면 새로 넣지 않는다(재공고는 ID가 다르니 새 행). 숫자만 Grep하지 않는다.
2. 행 추가:
   ```
   python -I -X utf8 .claude/skills/_공용/scripts/status_table.py add --company "<회사>" --job "<직무 옵션>" --type "<유형>" --deadline YYYY-MM-DD --link "[[<wiki 파일명>\|<공고 직무명 원문>]]" --id "<공고 ID>" --channel "<사이트>" --memo "YYYY-MM-DD 분석 — [[<output 파일명>\|지원 준비]]" --fit "<적합도>" --region "<지역>"
   ```
   | 열 | 값 |
   |---|---|
   | 기업명 | 2단계에서 정한 회사 이름. 게시 회사와 근무처가 다르면 게시 회사를 쓰고 메모에 `게시 <회사> → 근무 <회사>` |
   | 직무 | 값 목록의 낱말 **하나**. 맞는 게 없으면 사용자에게 묻는다(공고 직무명 원문은 "공고" 열 별칭에) |
   | 진행상태 | 새 행은 `Not started`(스크립트가 채운다), 최종 단계도 같다 |
   | 유형 | 공고 표기가 신입·인턴·채용연계 중 하나면 그것. "3년 이하"처럼 안 맞으면 비움 |
   | 서류마감 | `YYYY-MM-DD`. 공고에 없으면 비움. "채용 시 조기 마감"은 날짜가 있어도 메모에 |
   | 공고 ID | `jobkorea:50182629` 같은 값. 붙여넣기라 없으면 `—` |
   | 적합도 | 점수 스크립트의 `적합도` 값(`74 🟡`, 🚫가 있으면 뒤에 붙음). 점수를 못 냈으면 `미산출` |
   | 지역 | 근무지 낱말(`wiki-format.md`의 규칙). 모르면 `미기재` |
   - 종료 코드 3(같은 공고 ID)·2(값 오류)면 쓰지 않고 이유를 사용자에게 알린다.
3. 현황표 **전**에 이미 분석한 공고(wiki·output은 있는데 행이 없음)는 행을 넣되 진행상태는 사용자에게 묻는다.

### 상태 변경 요청
- 상태·메모·최종 단계를 고치는 일은 `/job-flow`의 몫이다. `.claude/skills/job-flow/SKILL.md`가 있으면 "`/job-flow`에서 해 주세요"라고 안내한다.
- **`/job-flow`가 아직 배포되지 않은 볼트에서만** 임시로 `status_table.py set-status --id <공고 ID> --state <값> [--note "…"]`를 쓴다(공고 ID가 `—`인 행은 `--company <회사> [--job <직무>]`). 말 → 값: "지원하기로 했어"·"서류 쓰기 시작" → `자소서 작성중` / "서류 다 썼어" → `자소서 작성 완료` / "제출했어" → `지원완료` / "서류 붙었어" → `서류합` / 면접은 몇 차인지 물어 `1차면접`·`2차면접`·`최종면접` / "최종 붙었어" → `최종합` / "떨어졌어" → `불합` / "지원 취소했어" → `지원취소`. "붙었어"처럼 단계가 모호하면 묻는다. 스크립트가 뒤로 가는 변경과 `최종합`·`불합`·`지원취소` 행의 덮어쓰기를 거부한다. 상태를 바꾸기 전에 사용자에게 무엇을 바꿀지 보여 주고 확인받는다.
- 입사·입사포기·무응답·지원안함은 진행상태 값이 아니다 — 메모에만 적는다.

## 5.5 마감 캘린더 갱신
행을 넣거나 일정이 바뀌면 매번:
```
python -I -X utf8 .claude/skills/_공용/scripts/calendar_export.py build
```
- `Areas/취업/마감 캘린더.md`와 `Areas/취업/내보내기/지원 마감.ics`를 새로 만든다(자동 생성 사본이라 덮어써도 된다). 날짜는 항상 KST 오늘로 확정한다.
- 공고에 서류 발표·역량검사·면접 같은 **일정이 적혀 있으면**(추정 금지) 사용자에게 "일정으로 넣을까요?"를 묻고 그러자고 하면 `calendar_export.py add-event --company … --kind 면접 --date YYYY-MM-DD [--time HH:MM] [--place …] [--memo …]`로 `Areas/취업/일정.md`에 한 줄 넣은 뒤 다시 `build`한다.
- 출력의 마지막 줄 "마감 3일 이내이거나 지난 지원 전 행"을 보고 끝에 한 줄로 옮긴다.
- 캘린더를 어디에 쓰나: Notion 모드가 꺼져 있으면(기본) `마감 캘린더.md` + `.ics`. Notion 반영은 사용자가 시킬 때만(이 스킬은 Notion에 쓰지 않는다).
- `.ics`를 구글 캘린더·폰에 가져오면 일정이 한 번 들어간다(자동 동기화 아님). 같은 파일을 다시 가져오면 중복될지 갱신될지는 앱마다 다르다 — 이 도구에서는 아직 시험하지 않았다. 중복이 생기면 먼저 가져온 일정을 지우고 새 파일을 가져온다.
