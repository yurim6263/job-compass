# /job-flow — 입구 · 오늘 현황 · 상태 갱신 · 통계

볼트 루트에서 실행한다. 날짜·D-day·정렬·통계·파일 존재 판정은 **스크립트**가 하고, 모델은 결과를 보여 주고 사용자의 말을 상태 값으로 옮긴다. 이하 `$S` = `.claude/skills/_공용/scripts`.

## 하는 것 / 하지 않는 것
- 쓰는 파일: **현황표**(진행상태·상태일·최종 단계·메모만, `status_table.py`로) · `Areas/취업/오늘 현황.md`와 `_widget/오늘 현황.json`(덮어써도 되는 사본, `dashboard.py today --write`) · 후보함 상태(지원예정/건너뜀만). 그 밖은 읽기만. `wiki/`·`raw/`·`output/`·`Notes/`는 고치지 않는다.
- **일을 직접 하지 않는다.** 단계를 판정해 다음 스킬을 **제안**만 한다(최대 3개, 이유 한 줄). 고르면 그 스킬로 넘어간다. 자동 실행 없음.
- Notion은 사용자가 시킬 때만(처음 연결·일괄 반영·수집 공고 올리기·Notion에서 가져오기·밀린 반영, 아래 "Notion"). 지원서 제출·메일 발송은 하지 않는다. 개인정보(연락처·학번)는 다루지 않고, 메모에는 제3자 연락처·이메일을 받지 않는다(이름·역할까지만).
- 모든 날짜는 KST. 현황표 형식이 깨져 있으면 읽은 만큼만 보여 주고 **고치지 않는다**(`status_table.py check` 결과를 알려 준다).

## 상태 갱신
1. **대상 찾기** — 회사명으로 `status_table.py find --company <회사>`. 2건 이상이면 공고 ID·직무를 보여 주고 고르게 한다(이름으로 추측하지 않는다).
2. **새 상태 확정** — 말 → 값(`_공용/references/status-values.md`): "지원하기로 했어"·"서류 쓰기 시작" → `자소서 작성중` / "서류 다 썼어" → `자소서 작성 완료` / "제출했어" → `지원완료` / "서류 붙었어" → `서류합` / 면접은 몇 차인지 물어 `1차면접`·`2차면접`·`최종면접` / "최종 붙었어" → `최종합` / "떨어졌어" → `불합` / "지원 취소했어" → `지원취소`. **"붙었어"처럼 모호하면 선택지로 묻는다**(서류합/최종합/기타). 입사·입사포기·무응답은 상태 값이 아니라 메모에만 적는다.
3. **변경 내용을 보여 주고 확인받는다**: `A사 · 지원완료 → 서류합 · 상태일 오늘 · 최종 단계 서류합`.
4. 뒤로 가는 이동(예: `서류합` → `지원완료`)은 "정말 되돌릴까요?"로 한 번 더 묻고, 확인했을 때만 `--allow-back`을 붙인다. 건너뛰기(예: `지원완료` → `1차면접`)는 허용한다. **단, 사용자가 "방금 잘못 눌렀어/취소해 줘"라고 한 실수 취소는 `--allow-back`이 아니라 아래 "실수 취소"로 한다**(`--allow-back`은 최종 단계와 메모를 못 되돌린다).
5. `python -I -X utf8 $S/status_table.py set-status --id <공고 ID> --state <값>(공고 ID가 `—`인 붙여넣기 공고는 `--id` 대신 `--company <회사> [--job <직무>]`로 지정하고, 둘 이상이면 스크립트가 고르지 않으니 사용자에게 고르게 한다) [--note "<한 줄>"] [--allow-back]` — 상태일(오늘 KST)·최종 단계(더 높을 때만, `불합`·`지원취소`가 돼도 보존)·메모가 갱신되고 수정 전 사본이 `Areas/취업/_백업/`에 남는다. `최종합`·`불합`·`지원취소` 행은 덮어쓰지 않는다.
6. **`set-status`가 끝나면 곧바로** `python -I -X utf8 $S/dashboard.py today --write`를 돌려 `오늘 현황.md`·`_widget/오늘 현황.json`을 새로 만든다(이 출력은 사용자에게 다시 보여 주지 않아도 된다. 안 하면 사본이 옛 상태로 남는다). 이어서 `dashboard.py steps --id <공고 ID>`(ID가 `—`이면 `--company`·`--job`)의 "다음 행동" 한 줄을 알려 준다. 상태가 `서류합`·`역량검사`·`1차면접` 등으로 바뀌면 "이 일정이 있나요?"를 **한 번** 묻고, 있다고 하면 `calendar_export.py add-event …` 후 `build`.
7. **`불합`·`지원취소`가 되면 한 번만, 선택으로**: 면접 후기 기록 제안(`/mock-interview 후기기록`) + 채용서류 반환 청구 같은 권리 체크리스트. 조문·기한·적용 범위는 **그때 검색해서 출처·기준일과 함께** 안내하고 외워 둔 숫자를 쓰지 않는다. 법 개정 여부는 단정하지 않는다.

## 실수 취소 ("방금 거 잘못 눌렀어", "취소해 줘")
**직전에 한 상태 변경 한 번**만 깨끗하게 되돌린다(진행상태·상태일·최종 단계·메모 4칸이 변경 전 값으로 돌아간다).
1. `python -I -X utf8 $S/status_table.py undo-status` (미리보기). 어떤 칸이 어떻게 바뀌는지 **그대로 보여 주고** "이대로 되돌릴까요?"를 묻는다.
2. 확인하면 `python -I -X utf8 $S/status_table.py undo-status --apply`. 수정 전 사본이 `Areas/취업/_백업/`에 남는다. 한 번 되돌리면 같은 기록으로 다시 되돌릴 수 없다. 적용한 뒤에는 `dashboard.py today --write`로 `오늘 현황` 사본도 다시 만든다.
3. 기록이 없거나(직전 변경이 없음) 그 행이 그 뒤 또 바뀌었으면 스크립트가 거부한다(종료 코드 4). 이때는 임의로 표를 고치지 않고 이유를 알린 뒤, 사용자가 원하면 `set-status --allow-back`(최종 단계·메모는 남는다고 미리 알림)이나 직접 수정을 제안한다.
4. 이 경로는 **방금 한 변경의 실수 취소 전용**이다. 이미 한참 지난 상태를 바꾸는 일은 위 "상태 갱신" 4번(뒤로 가기 확인)으로 한다.

## 후보 → 현황표
- 후보함(`Areas/취업/공고 후보함.md`)에서 사용자가 고른 건은 **`/job-posting`을 호출**한다(미리보기 점수는 임시 폴더에만 있으므로 정식 저장은 `/job-posting`이 본문을 다시 받아서 한다).
- `/job-posting`이 현황표에 `Not started` 행을 추가하면 후보함의 그 줄 상태를 `지원예정`으로 바꾼다: `python -I -X utf8 $S/candidates.py set-state --id <공고 ID> --state 지원예정`(스크립트가 없는 볼트에서는 후보함 상태 칸만 Edit).
- "건너뛸래"라고 하면 후보함 상태만 `건너뜀`으로(삭제 없음).

## 후보함 정리
후보함에는 **볼 만한 공고만** 둔다(2026-11-02 사용자 결정). 걸러낸 공고는 지우지 않고 `Areas/취업/_수집기록.md`에 이유와 함께 남는다.
- "후보함 정리해줘" — `python -I -X utf8 $S/candidates.py tidy --check-career`(경력 정보가 없는 후보는 사이트 요약 칸의 경력을 한 건씩 확인 · 미리보기: 남김·수집 기록으로·지난으로 접음 목록)를 **그대로** 보여 주고, OK면 `tidy --apply --check-career`. 사용자가 `지원예정`·`건너뜀`으로 둔 행은 건드리지 않는다.
- "걸러낸 공고 보여줘" — `candidates.py filtered [--days 7]`.
- "이거 후보함에 넣어줘"(잘못 걸러짐) — 공고 ID를 확인하고 `candidates.py restore --id <공고 ID>`.
- "현황표의 ○○를 후보함으로 되돌려줘"(아직 지원하기로 정하지 않은 공고) — `candidates.py from-table --id <공고 ID>`(또는 `--company`·`--job`) 미리보기를 보여 주고 OK면 `--apply`. `Not started` 행만 되돌린다(진행한 행은 거부). 현황표 사본이 `_백업/`에 남고, raw·wiki·output 공고 문서는 그대로 둔다. Notion에 이미 올린 행이 있으면 Notion 쪽은 지우지 않는다고 알린다(삭제는 사용자가).
- 기준을 바꾸고 싶다고 하면 `Areas/취업/검색 조건.md`의 `제외 직무 낱말`·`점수 기준`(기본 60)·`후보 접는 기간`(기본 14일)·`후보 최대 N건`(권장 10) 칸을 보여 주고, 사용자가 정한 값으로 그 칸만 고친다(행이 없으면 `## 조건` 표에 추가).

## Notion
규칙 전체는 `_공용/references/notion.md`(표 6개·올리지 않는 것·미리보기와 확인·삭제 없음). 계산은 `python -I -X utf8 $S/notion_sync.py …`.
- **"Notion 연결해줘" / 처음 설정** — notion.md "처음 연결" 1~4. 끝나면 사용자에게 `설정.md`의 `notion`을 `on`으로 바꿀지 묻고, OK면 그 칸만 고친다.
- **"Notion에 올려줘"(지원 현황)** — `notion_sync.py plan --table 지원현황` → 만들기/고치기/같음 개수와 표 미리보기 → 확인 → 쓰기 → 건마다 `record`. 상태 갱신 직후 `notion`이 `on`이면 "이 변경도 Notion에 반영할까요?"를 한 번 묻는다(그 행 `--key`만).
- **"수집 공고도 올려줘"** — 기준 점수를 묻고(기본 70) `plan --table 수집공고 --min-score N`. 점수가 없는 후보는 올리지 않는다(사용자가 "다 올려"라고 하면 `--min-score` 없이).
- **"Notion에서 가져와"** — notion.md "Notion → 볼트". 차이는 고르지 않고 보이기만, 사용자가 고른 칸만 위 "상태 갱신" 순서로 반영.
- **밀린 반영** — 오늘 현황에 `Notion 밀린 반영 N건`이 보이면 그 줄을 그대로 보여 준다. "올려줘" → `pending list`의 건마다 해당 표의 값 만들기부터. "버려" → `pending clear`.
- 무인 실행(예약 스캔)에서는 이 구획을 쓰지 않는다.

## 서류 형태 판별
공고 wiki(`wiki/채용공고_…`)의 제출·전형 절에서 자소서 요구 여부를 본다. 자소서가 없으면 `/cover-letter`를 제안하지 않고 "이력서·과제형"이라고 알린다. 확정할 수 없으면 "공고에서 확인 필요".

## 첫 실행 안내
