# 모드별 질문 · 체크리스트 기준

이 문서는 이 저장소에서 새로 쓴 것이다. 질문은 **영역 목록에서 직전 답변에 맞춰 만든다**(고정 질문지를 읽지 않는다).

## 체크리스트 1~10 — 예의 기준 (관찰 가능한 것만)
| # | 항목 | 예의 기준 |
|---|---|---|
| 1 | 질문에 답했다 | 질문이 묻는 것을 직접 말했다(어긋나면 정답을 알려 주지 않고 확인 질문으로 되묻기) |
| 2 | 결론을 먼저 말했다 | 첫 두 문장 안에 결론/핵심이 있다 |
| 3 | 구체 사례가 있다 | 프로젝트·상황이 특정되고 "누가·언제·무엇을"이 있다 |
| 4 | 내 역할이 구분된다 | 팀 성과와 내가 한 일이 나뉘어 있다 |
| 5 | 근거가 있다 | 수치·전후 변화·검증 방법 중 하나 이상(없으면 `수치 없음`이 아니라 `검증 방법 없음`을 지적) |
| 6 | 판단 이유가 있다 | "왜 그 방법이었는지"와 대안 언급이 있다 |
| 7 | 사실이 서류와 일치한다 | 카드·자소서·제출 이력서의 숫자·역할·기간과 같다. 다르면 어느 쪽이 맞는지 되묻는다 |
| 8 | 분량이 맞다 | 안내한 시간·분량의 0.5~1.5배(발화 약 3.5음절/초 기준 글자수로 환산). 실제 시간은 측정할 수 없다 |
| 9 | 어조가 실행형이다 | "~해 왔습니다"형이 중심이고 "~하고 싶습니다"만 반복하지 않는다 |
| 10 | (해당 시) 입사 후 적용에 근거가 있다 | 기업 조사의 키워드·화두와 연결됐다. 회사 이름을 바꿔도 성립하면 아니오 |
- 해당 없는 항목(예: 10번, 사례를 묻지 않는 문항의 3번)은 `null`로 두어 분모에서 뺀다(`산정 n/m`). 항목을 **예로 줄 때는 답변 인용 한 줄**이 필요하다(스크립트가 없으면 오류를 낸다).
- 역질문은 체크리스트가 아니라 ① 공고·조사에 근거한 질문인가 ② 검색하면 바로 나오는 질문은 아닌가 ③ 기업 조사의 화두와 닿는가로 본다.

## 강도
순한맛(격려, 꼬리 1단계) · 보통(꼬리 적절히, 추천) · 매운맛(압박 어투, 꼬리 2단계 연속, 수치·근거를 강하게). 도중에 바꿀 수 있다. 같은 모드·같은 강도끼리만 성장 추이를 비교한다.

## 인성
지원동기 · 강점/약점 · 갈등 · 협업 · 성장. 결론-이유-요청/문제-역할-행동-결과 구조, "~하고 싶습니다" vs "~해 왔습니다" 어조, 입사 후 적용(기업 조사의 `apply_plans`)에 근거가 있는지. 경험 진술에는 "그때 구체적으로 무엇을 했나요?"(BEI 탐침)로 파고든다.

## 기술 — 세 트랙 (영역 목록)
| 트랙 | 영역 |
|---|---|
| 제조AI/CBM | 센서·진동 시계열 전처리, 특징 추출, 예지보전(RUL)과 이상탐지의 차이, 라벨 부족·불균형, 평가 지표 선택, 과적합 방지(시간 순 분할), 현장 배포·지연·엣지 제약, 데이터 품질·결측 |
| LLM응용 | RAG 구조(청킹·임베딩·검색·재순위), 프롬프트 설계, 환각 대응, 평가 방법, 비용·지연, 보안(프롬프트 주입), 도구 호출 |
| 데이터/MLOps | 파이프라인, 버전 관리, 드리프트 모니터링, 재학습 기준, 재현성 |
- **카드 딥다이브**: 카드 `keywords`·`action`·`change`에서 "왜 이 기술/방법을 골랐나 → 대안은 → 트레이드오프는 → 결과를 어떻게 확인했나 → 다시 한다면"을 직전 답을 보고 이어 간다. 카드에 없는 수치를 물을 때는 "카드에 이 수치가 없다"를 내부 메모로 두고, 답이 나오면 **새 사실로 리포트에 적고 카드 보강을 제안**한다(카드에 자동으로 쓰지 않음).
- **선택: AI 도구 활용 과제**(E-2): 사용자가 AI 도구로 과제를 푼 과정을 설명하게 하고 리뷰에 `검증 근거`·`수정 이력` 항목을 둔다(없으면 개선점).
- 점수의 갭 항목(공고 요건인데 카드가 없음)은 약점 질문 1문항으로.

## 컬처핏
기업 조사의 인재상 키워드로 질문한다. "왜 이 회사인가"는 **치환 테스트**: 회사 이름을 바꿔도 성립하면 지적한다. 인재상 키워드마다 사용자의 실제 경험(카드) 한 건을 끌어내게 한다.

## 공통 꼬리질문 5세트
어떤 문제였나 / 왜 그 방법이었나 / 내 역할 범위는 / 결과를 어떻게 확인했나 / 다시 한다면 — 직전 답변을 보고 필요한 것만 쓴다.

## 방어 상태 판정 (스크립트가 한다)
1~7번 중 예 5개 이상 + 7번 예 = `ready` / 일부 부족 = `weak` / 답을 못 함 = `unprepared`. 기준은 공고 5건·세션 몇 번 뒤 보정한다.
