# /job-scan 소스 (모두 "이 PC에서 시험한 정도"를 같이 적는다)

원칙: 목록은 **정확한 원문이 아니라 후보를 찾는 용도**라서 WebFetch의 요약 결과도 쓸 수 있다. 다만 공고 본문(미리보기 점수·정식 저장)은 `curl` 원본을 쓴다. 한 소스가 실패해도 나머지는 계속한다. 무인 실행에서는 브라우저 확장을 쓰지 않는다.

| 순위 | 소스 | 방법 | 시험 상태 |
|---|---|---|---|
| 1 | 사람인 | 검색 결과 페이지(`https://www.saramin.co.kr/zf_user/search/recruit?searchword=<검색어>`). Open API(`oapi.saramin.co.kr`)가 있고 **이용신청 후 승인**이 필요하다(로그인이 필요해 사용자만 가능, 키는 볼트에 쓰지 않는다) | **2026-11-01 실사이트 시험: 현재 방법으로는 읽히지 않음.** WebFetch는 "채용공고를 찾고 있습니다" 로딩 문구만 받고(제목에 `총 N건`만 보임) 개별 공고가 없다. 기본 `curl`은 307 → `HTTP_BAD_REQUEST` 오류 페이지. 차단·캡차·로그인 안내는 없었다. 브라우저인 척하는 요청 헤더로 우회하지 않는다. 막히면 건너뛰고 `_scan-log.md`에 이유를 남긴다. 사람인을 쓰려면 Open API 신청이 필요하다 |
| 2 | 잡코리아 | 검색 결과 페이지(`https://www.jobkorea.co.kr/Search/?stext=<검색어>`) | **2026-11-01 실사이트 시험 통과.** WebFetch로 검색어당 20건(회사·제목·링크)이 읽혔고, `curl` 원본도 200(약 430KB, 공고 링크 고유 25개). **목록에 마감일이 거의 없다** → 후보함에 "마감 여부 미확인"으로 두고 상위 K건만 상세에서 확인. 목록 제목에는 없던 "경력 2년 이상"이 본문에 있어 점수 단계에서 🚫로 잡혔다(1차 선별은 제목만 본다). robots.txt: `Claude-User`는 로그인·내정보·기업관리 경로만 막고 공개 검색·채용 페이지는 허용(`ClaudeBot` 등 학습용 크롤러는 전체 차단) |
| 3 | 원티드·점핏 | 목록이 스크립트로 그려져 `curl`로 어렵다 | 미시험. 브라우저 확장(읽기만)으로 사용자가 직접 부를 때만 |
| 4 | 웹 검색 보조 | 위가 부족할 때만. 마감 확인이 안 되므로 `모집 여부 직접 확인` 라벨 필수 | 미시험 |
| 5 | 공공기관·공기업 | 잡알리오 등 공식 사이트 | **이 사용자는 `끔`.** `검색 조건.md`의 `공공기관·공기업`이 `끔`이면 실행하지 않는다 |
| 시험용 | 로컬 서버 | 개발 중 시험에는 사용자가 지정한 주소(예: `http://localhost:8765/list.html`)를 소스로 쓴다 | 이 저장소의 가짜 시험에서만 |

## 후보 정규화
- 회사·직무(제목)·링크·공고 ID·마감(있을 때만 `YYYY-MM-DD`)·지역(근무지 낱말: 서울·경기·대구·부산·울산·포항·그 밖·원격·미기재)·소스 이름.
- 제목 앞뒤 꼬리표(`[…]`)는 그대로 둔다(후보함은 사용자가 읽는 목록). 광고·"추천 공고"는 후보가 아니다.
- 검색어는 `candidates.py conditions`가 낸 목록(키워드 칸의 `/` 구분마다 한 줄)을 쓴다. 검색어 하나당 상위 몇 건만 읽는다(N 상한을 넘기지 않게).

## 사이트 이용
공개 검색 페이지를 사람이 보는 정도로만 읽는다(요청 사이를 두고, 하루 1회 · 검색어 수만큼). robots.txt는 2026-11-01에 확인했다(사람인: 검색 목록 경로에 규칙 없음, 일부 공고 상세 경로만 제한 / 잡코리아: 위 표). **이용약관 본문은 아직 읽지 않았다**(공개 전 점검, 사용자 확인). 검색어가 여럿이면 후보가 상한(N)에 걸릴 수 있어, 후보에 `query`(찾은 검색어)를 적으면 스크립트가 검색어별로 번갈아 담는다.
