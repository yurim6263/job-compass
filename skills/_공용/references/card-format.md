# 경험 카드 형식 (`/exp-organize`가 쓰고 `verify_cards.py`가 검사한다)

기준 문서: 기획 `00_공통-규약.md` §1. 이 파일은 스킬이 바로 읽는 요약이다. 예시는 모두 가상이다.

## 프로젝트 문서 `wiki/내경험_<프로젝트>.md`

```
---
tags: [내경험, 프로젝트, 제조AI]
sources:
  - "[[Projects/SecondBrain/raw/내경험/깃허브/<저장소>/커밋요약|커밋요약]]"
updated: YYYY-MM-DD
origin: 팀            # 본인작성 | 팀 | 교육과제 | 받은교재 | 미정 | 혼합(한 문서에 origin이 다른 카드가 있을 때)
---

# <프로젝트 이름>

## 개요          ← 기간·팀 규모·원천 목록 (모두 근거 링크)
## 자료 간 차이   ← 같은 사실이 원천마다 다를 때 표로 둘 다 적는다 (규칙 10). 고르지 않는다
## 경험 카드
### exp-YYYYMMDD-NN 카드 제목
- origin: …
…
```

- 파일 하나가 프로젝트 하나다. 카드는 여러 장일 수 있다. 같은 프로젝트의 원천은 sources에 전부 단다.
- 링크는 볼트 루트부터 전체 경로 + 짧은 이름 별칭. md가 아닌 파일은 확장자까지(볼트 규칙 3).

## 카드 한 장 (`### exp-YYYYMMDD-NN 제목` 아래 `- 필드: 값` 줄)

| 필드 | 필수 | 값 |
|---|---|---|
| `origin` | Y | `본인작성` `팀` `교육과제` `받은교재`(카드를 만들지 않는다) `미정`(사용자에게 묻는다) |
| `title` | Y | 경험 한 줄 |
| `problem` | Y | 무엇이 문제였나 |
| `role` | Y | 그중 **내** 역할. 팀이면 내가 한 것만. "우리가/팀이" 금지 |
| `action` | Y | 내가 바꾼 구체 행동 |
| `change` | Y | 전→후 변화. 수치가 없으면 정성 서술이나 `[수치 확인 필요]` |
| `numbers` | N | 맨 앞에 판정: `O`(있음) `△`(`[수치 확인 필요]` 포함) `X`(없음). 예: `O F1 0.89` |
| `job_link_tags` | N | `제조AI` `설비데이터` `예지보전` `CBM` `시계열예측` `ML/DL` `LLM응용` `데이터파이프라인` `프론트/웹` 에서만 |
| `keywords` | Y(사실상) | 기술·도구·방법·도메인 낱말. **근거 파일 본문에 실제로 나온 낱말만** |
| `question_types` | N | `지원동기` `직무역량` `문제해결` `협업` `성장` `AI활용` `입사후포부` 에서만 |
| `ai_usage` | N | `{tool, task, effect}` 셋 다 있을 때만. 사용자가 확인한 사실만 |
| `evidence` | Y | `[[raw 링크|이름]] — 위치(섹션·커밋 범위·쪽)`를 줄마다. 1개 이상. 아래에 `  - ` 들여쓰기 줄로 여러 개 |
| `fact_status` | Y | `자료확인`(raw에 적힌 그대로) · `본인진술`(대화로 들음) · `미확인`(raw끼리 충돌, 평가·정리용 문장, 근거 없는 주장) |

값이 모르는 곳은 `[확인 필요]`로 둔다. 지어서 채우지 않는다. 해석·추론은 `> 해석:` 블록으로 카드 밖(또는 카드 끝)에 둔다.

### 예시 (가상)

```
### exp-20261031-01 설비 센서 로그 전처리와 LSTM 이상 탐지 모델 담당
- origin: 팀
- title: 센서 로그의 결측·이상치 처리 규칙을 만들고 LSTM 이상 탐지 모델과 평가를 맡음
- problem: 센서 로그에 결측과 이상치가 섞여 있어 사람이 그래프로 보고 판단하느라 고장 징후를 늦게 발견함
- role: 4명 팀에서 데이터 전처리, LSTM 모델, 평가 스크립트를 맡음(프론트·API는 다른 팀원)
- action: 결측은 앞뒤 값으로 보간, 평균에서 3표준편차 밖은 이상치로 표시하는 규칙을 문서화하고 구현함. 윈도우 길이 30·60·120을 비교함
- change: 윈도우 60에서 가장 안정적이었고 검증셋 F1은 자료마다 다르게 적혀 있음 [수치 확인 필요]
- numbers: △ F1 0.89 / 0.912 / 약 0.91 [수치 확인 필요]
- job_link_tags: [제조AI, 설비데이터, 시계열예측]
- keywords: [LSTM, 전처리, 윈도우, F1]
- question_types: [직무역량, 문제해결]
- evidence:
  - [[Projects/SecondBrain/raw/내경험/깃허브/project-a-anomaly/작성자통계|작성자통계]] — 내 커밋 10건, 만진 영역 src·docs
  - [[Projects/SecondBrain/raw/내경험/깃허브/project-a-anomaly/문서/docs__data-rules.md|data-rules]] — 처리 규칙 전문
- fact_status: 자료확인
```

## 만들지 않는 카드
- 근거(`evidence`)가 없는 것 · `받은교재` · 평가·정리용 문장만 있는 것(그 문장은 `> 해석:` 또는 `미확인`).
- 면접에서 1분에 설명 못 할 수치.
