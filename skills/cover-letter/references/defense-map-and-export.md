- 문항 제목은 `### 문항 N …` 형식이어야 `cl_check.py`가 읽는다.
- 한 파일 안에 버전을 쌓고 이전 버전은 접어 둔다. 덮어쓰기 전 `.bak-날짜` 사본.
- 근거가 되는 사실은 모두 wiki 카드에 있다. 이 문서에는 카드 id와 증거 위치만 적는다.

## 방어 맵 `Areas/취업/자소서/<회사>_<직무>_방어맵.md`
| id | 문장 | 위치 | 유형 | 꼬리질문 2개 이상(질문 / 확인 의도 / 난이도) | 1분 답변 골자 | 방어 상태 |
|---|---|---|---|---|---|---|
| dm-001 | "…" | 2번 문항 2문단 | 수치·기술선택·역할범위·성과·갈등판단 | … | **사용자가 확인하기 전에는 비움** | ready · weak · unprepared |
- 꼬리질문 5세트(어떤 문제였나 / 왜 그 방법이었나 / 역할 범위는 / 결과를 어떻게 확인했나 / 다시 한다면)에서 문장별 2개 이상.
- 미끼(유지할 문장)는 **5개 이상**을 목표로 하되 카드가 적으면 가능한 수만 만들고 이유를 쓴다.
- **위험 문장 테스트**: 1분 안에 설명할 수 있는 문장 = 미끼(유지), 설명 못 하는 수치·주장 = 위험(수정·삭제 제안). 판정은 사용자의 답으로 한다.
- `1분 답변 골자`는 사용자가 답을 준 것만 쓴다. `/mock-interview`가 `weak`·`unprepared`를 먼저 출제하고 면접 뒤 방어 상태를 갱신한다(양방향).

## 내보내기 조건 (모두 통과해야 `.docx`)
1. `[수치 확인 필요]`·`[추정]` 잔존 0 (`cl_check.py placeholders` 종료 코드 0)
2. `근거 없음` 문장이 없거나 사용자가 "이 문장은 내 진술이다"라고 확인
3. 글자수 한도 이내 (`cl_check.py chars`에 `--limits`)
4. 일관성 검사의 미해결 충돌 0 또는 사용자 확인
5. 인간화 점검(치환 테스트 2종 + AI풍 신호) 실시
파일: `Areas/취업/내보내기/<회사>_<직무>_자소서.docx`(사본, 덮어써도 됨). 도구 실패 시 마크다운 최종본만 남기고 이유를 보고한다.
