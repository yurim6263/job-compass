# wiki · output 구성

## wiki `P/wiki/기업조사_<회사>.md` — 사실만 (회사당 하나, 고쳐 쓴다)
frontmatter `tags: [기업조사, <회사>, <업종>]`, `sources`에 raw 파일 전부, `updated`. 절:
1. 한 문단(무슨 회사인지, 소스 표현으로) + "원문은 raw에 있다."
2. `## 한눈에 보기` — 업종·설립·대표·본사/사업장·상장 여부·직원 수(출처·기준일). 못 얻은 칸은 `(출처 미확보)`
3. `## 재무` — 5지표 표(사업연도·출처). 비상장 폴백이면 이유 한 줄
4. `## 회사가 스스로 적은 것` — 비전·인재상·핵심가치·CEO 메시지(원문 표현을 따옴표로, 연도 명시)
5. `## 사업과 제품` — 주력 제품·서비스·공정, 공개된 기술·사례
6. `## 최근 뉴스` — 날짜·매체·한 줄(6개월, 5건 이상 목표)
7. `## 평판 (집계)` — 불만 Top 3, 키워드 빈도 정도. 작성자 정보 없음, 인용은 익명·짧게. 표본 1~2건이면 `표본 부족`
8. `## 채용·전형` — 수시/공채, AI 서류평가·AI역량검사·컬처핏·코테 AI 허용(각각 허용/금지/미확인 + 출처)
9. `## 자료 간 차이` — 소스끼리 값이 다를 때 양쪽을 그대로(볼트 규칙 10)
10. `## 관련 문서` — 이 회사의 공고 wiki, output 링크
갱신: 새로 만들지 않고 고친다. 오래된 값은 새 값으로 바꾸되 조회일을 항목마다 적는다(이전 값의 raw는 그대로). 고치기 전 `.bak-날짜` 사본.

## output `P/output/YYYY-MM-DD <회사> 기업분석.md` — 내 경험과의 대조
맨 위 **요약 블록**(다음 스킬이 앞부분만 읽는다, 1,500자 이내):
```
<!-- company-summary v1 -->
- 회사: / 직무: / 공고 wiki: [[...]] / 조사일: / 모드:
- 핵심 키워드(5~10):
- "팀원처럼" 화두(3):
- 키워드 반영 가능률: O n · 모호 n · X n → n% (산정 n/m)
- 지원 판단: 권장|조건부|신중 · 한 줄 이유
- 근거 부족 항목:
<!-- /company-summary -->
```
이어서: `## 키워드 체크리스트`(키워드 | 소스 | 내 매칭 O·모호·X | 카드 id | 근거 한 줄 · 핵심 3개 표시) → `## "이미 팀원처럼"`(과제 3개(추정)+근거 링크, 화두 3개+닿는 카드 id, 역질문) → `## 지원 판단`(`company_calc.py` 출력 그대로 + GAP 표) → `## 자소서·면접 활용 가이드`(키워드를 구체 경험 뒤에 배치하라는 제안만, 몰아 넣기 제안 금지) → `## 입사 후 적용 제안`(선택) → `## 관련 문서`.
- 표 칸에는 사실과 링크만, 해석은 `> 해석:` 블록.

## 입사 후 적용 (`apply_plans`)
- 후보 카드는 체크리스트 O·모호 항목과 화두에 닿는 **3장 이하**(4장 이상이면 겹치는 항목이 많은 순, 같으면 `numbers`가 있는 순).
- 형식: `> 해석(입사 후 적용, <회사> <조사일>): [회사의 과제·키워드]에 [카드의 행동·변화]를 적용해 [기대 변화]` + 근거(체크리스트·화두 원문)와 output 링크. 계획·가정임을 숨기지 않는다.
- 사용자가 저장을 확인한 뒤에만 카드에 쓴다.
